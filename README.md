# 热档片间（Hotbay）

影院素材分区温层：登记 → 冷热迁移 → 保留销毁 → 目录互证。

- 前端 http://127.0.0.1:6300
- API http://127.0.0.1:11300
- `docker compose up -d --build`

## 登记成功灯（唯一口径：以占用∪册面∪目录键可重放为准）

「已登记」不是写入时的一纸宣称，而是可被重放的证据。登记成功必须同时满足：

1. **分区册行**：`partitions` 有该 `part_key` 的行；
2. **素材段**：`clips` 至少一段，且每段对象键都在湖目录中有对应键、字节一致；
3. **湖对象键**：`inventory_objects` 一侧齐全；
4. **占用谓词**：状态为「在册」的分区计入其片库间额度（全库唯一谓词）。

四侧同命运重放，任一侧不成立即视为**假登记**：

- 写入口在同一事务（`BEGIN IMMEDIATE`）内落册行、素材段、目录键与成功流水，
  提交前先跑一遍证据重放；不过即整笔回滚，并另起事务补失败流水，
  占用前后相等，证明回到登记前快照。
- 读路径（登记流水分页、分区册、目录清单、容量页、总览在册计数条）**不缓存成功面**，
  一律按证据重放裁决：证据不成立的成功流水显示「回退」并给出缺口原因；
  总览 `登记缺口`、片库间 `登记缺口` 与分区册「证据」列同数同源。
- 保留策略「连目录销毁/只标过期」属合法证据拆除：`已销毁` 不再强求留存；
  `已过期` 仍要求段与目录键齐全，占用谓词自然归零。

## 其他约定

- 片库间额定在册分区数即硬闸：达额定则整笔登记失败，不留分区、素材段与目录增量；
  失败登记不计入任何读路径占用。
- 并发抢同一库名额由库级写锁排队，后到者重放同一占用谓词，不得双破硬闸。
- 目录键行与分区册同生同死：对象键已存在即整笔拒绝，绝不静默覆盖。
- 每笔登记（成/败）落登记审计流水（`GET /api/登记审计`），含占用前→后/额定与失败原因，
  可与回执、容量页对照。
- 后端测试：`cd backend && python -m pytest tests/`
  （满容再登记、并发抢最后名额、半截失败脏写、目录缺键假登记收口、各读面一致性）。
